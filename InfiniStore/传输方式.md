# 一、项目定位

InfiniStore：LLM 推理场景下的 KV Cache 存储与传输系统。

- Client：发起 KV 读写请求。
    
- Service：负责 KV 存储、查询和传输。
    
- Python：模拟上游服务，负责判断 KV 应该访问哪个 Service。
    
- 不负责全局 KV 路由和位置查找。
    

Service 使用：

- `kv_map`：Key → PTR 映射。
    
- `lru_queue`：LRU 缓存管理。
    
- Memory Pool：管理 KV 内存。
    

# 二、RDMA 传输

## 1. 基本概念

|组件|作用|
|---|---|
|RQ|接收请求|
|SQ|提交 RDMA 操作|
|CQ|接收操作完成通知|
|CQE|完成事件|
|WR|提交给 SQ 的工作请求|
|`wr_id`|标识 WR，完成时找回对应任务|

两种主要数据操作：

- 上传：Service 发起 RDMA READ，从 Client 读取数据。
    
- 下载：Service 发起 RDMA WRITE，将数据写入 Client。
    

## 2. 修改前：单 Poller 集中处理

一个 CQ Poller，通过 `switch(wc.opcode)` 处理不同类型的完成事件。

```
             CQ Poller（单线程）
                     │
                ibv_poll_cq()
                     │
                switch(opcode)
                     │
          ┌──────────┴──────────┐
          │                     │
       RECV CQE             RDMA CQE
          │                     │
       解析请求             READ / WRITE
          │                  完成处理
       KV 查询                  │
       内存分配              更新 KV 状态
       LRU 操作              释放 PTR 引用
          │                     │
       提交 RDMA                 │
       READ/WRITE                │
          │                     │
          └──────────┬──────────┘
                     │
                  提交 ACK
```

特点： 请求接收、KV 管理、RDMA 提交、完成处理和 ACK 提交都集中在一个 Poller。

注意：提交 RDMA WR 后不需要等待网卡执行完成，Poller 可以继续处理其他 CQE。

## 3. 修改后：三个 Poller、四个队列

三个 Poller：

|Poller|职责|
|---|---|
|CQ Poller|接收 CQE、识别类型、分发任务|
|KV Poller|KV 查询、内存管理、LRU、完成状态更新|
|SQ Submit Poller|构造并提交 READ/WRITE WR、提交 ACK|

四个队列：

|队列|保存内容|
|---|---|
|`_recv_task_q`|新接收的请求元数据|
|`_rdma_submit_q`|等待提交的 RDMA READ/WRITE 任务|
|`_rdma_done_q`|已完成的 RDMA 操作及关联任务|
|`_ack_q`|等待发送的 ACK 任务|

另外：`_inflight_wr_map` 保存已提交、尚未完成的 WR，通过 `wr_id` 找回任务。

### 整体架构

```
              Poller 1
              CQ Poller
                  │
          ┌───────┴────────┐
          │                │
       RECV CQE        READ/WRITE CQE
          │                │
    _recv_task_q      _rdma_done_q
          │                │
          └───────┬────────┘
                  │
               Poller 2
               KV Poller
                  │
          ┌───────┴────────┐
          │                │
    _rdma_submit_q       _ack_q
          │                │
          └───────┬────────┘
                  │
               Poller 3
            SQ Submit Poller
                  │
          ┌───────┴────────┐
          │                │
       READ/WRITE        ACK SEND
          │
          ▼
        网卡执行
          │
          ▼
        产生 CQE
          │
          └──────► CQ Poller
```

## 4. 两种 RDMA 请求

上传：RDMA READ

```
RECV CQE
   ↓
_recv_task_q
   ↓
KV Poller：解析 Key、分配内存
   ↓
_rdma_submit_q
   ↓
SQ Poller：提交 RDMA READ
   ↓
网卡读取 Client 数据
   ↓
READ CQE
   ↓
_rdma_done_q
   ↓
KV Poller：更新 kv_map、LRU
   ↓
_ack_q
   ↓
SQ Poller：发送 ACK
```

下载：RDMA WRITE

```
RECV CQE
   ↓
_recv_task_q
   ↓
KV Poller：查询 kv_map、更新 LRU、引用 PTR
   ↓
_rdma_submit_q
   ↓
SQ Poller：提交 RDMA WRITE
   ↓
网卡写入 Client 内存
   ↓
WRITE CQE
   ↓
_rdma_done_q
   ↓
KV Poller：释放在途 PTR 引用
   ↓
_ack_q
   ↓
SQ Poller：发送 ACK
```

改造本质：不是改变 RDMA 操作，而是将原来集中在 CQ Poller 的 CPU 处理任务拆分成三个阶段。

# 三、TCP 传输

## 1. 基本设计

TCP 使用 libuv Event Loop 事件驱动模型。

不是每个请求创建一个线程，而是 Event Loop 统一监听多个 TCP 连接。

核心函数：

|函数|作用|
|---|---|
|`register_server()`|初始化服务端|
|`uv_tcp_init()`|初始化 TCP 句柄|
|`uv_tcp_bind()`|绑定 IP 和端口|
|`uv_listen()`|监听新连接|
|`on_new_connection()`|接受新连接|
|`uv_accept()`|接收连接|
|`uv_read_start()`|注册数据读取|
|`alloc_buffer()`|分配临时接收缓冲区|
|`on_read()`|接收、解析数据|
|`handle_request()`|解析请求并分发|
|`uv_write()`|异步发送数据|

## 2. TCP 连接流程

```
register_server()
       │
   uv_tcp_init()
       │
   uv_tcp_bind()
       │
    uv_listen()
       │
   Event Loop
       │
on_new_connection()
       │
   uv_accept()
       │
创建 client_t、client_handle
       │
   uv_read_start()
       │
    等待数据
```

注意：

- `server`：服务端监听句柄。
    
- `client_handle`：已建立的 Client 连接句柄。
    
- `client_t`：保存连接对应的业务状态。
    
- `handle->data = client`：将连接句柄与业务对象关联。
    
- `128`：`uv_listen()` 的 backlog 参数，不是线程数。
    

一个 TCP 连接可以处理多个请求，关闭连接后才释放对应资源。

## 3. TCP 接收状态机

```
READ_HEADER
READ_BODY
READ_VALUE_THROUGH_TCP
```

|状态|接收内容|
|---|---|
|`READ_HEADER`|固定协议头|
|`READ_BODY`|FlatBuffers 请求元数据|
|`READ_VALUE_THROUGH_TCP`|实际 KV 数据|

接收流程：

```
on_read()
    │
switch(client->state_)
    │
    ├── READ_HEADER
    │      接收 Header
    │      verify_header()
    │
    ├── READ_BODY
    │      接收 FlatBuffers
    │      handle_request()
    │
    └── READ_VALUE_THROUGH_TCP
           接收实际 KV
           memcpy 到 PTR
           更新 kv_map / LRU
           返回 ACK
```

三个重要变量：

- `offset`：本次接收缓冲区已经处理的位置。
    
- `bytes_read_`：当前阶段累计接收字节数。
    
- `expected_bytes_`：当前阶段需要接收的总字节数。
    

它们用于处理 TCP 分段接收。

## 4. TCP PUT / GET

PUT：Client 上传 KV

```
Client: w_tcp()
      │
      ├── 发送 Header + Body
      │
      ▼
Service: on_read()
      │
      ▼
handle_request()
      │
      ▼
tcp_payload_request()
      │
      ├── 分配 KV 内存
      └── 切换 READ_VALUE_THROUGH_TCP
                │
                ▼
         Client 发送实际 KV
                │
                ▼
         on_read() 接收数据
                │
                ▼
         memcpy 到 PTR
                │
                ▼
         更新 kv_map / LRU
                │
                ▼
             ACK
```

GET：Client 下载 KV

```
Client: r_tcp()
      │
      ├── 发送 GET 请求
      │
      ▼
Service: on_read()
      │
      ▼
handle_request()
      │
      ▼
tcp_payload_request()
      │
      ├── 查询 kv_map
      ├── 更新 LRU
      └── 获取 PTR
              │
              ▼
          uv_write()
              │
              ▼
       发送实际 KV 数据
              │
              ▼
            Client
```

# 四、最后记住这张对比表

|对比|TCP|RDMA|
|---|---|---|
|监听方式|libuv Event Loop|CQ Poller|
|接收入口|`on_read()`|`cq_poll_handle()`|
|数据接收|Socket 字节流|RQ|
|数据发送|`uv_write()` / `sendmsg()`|SQ|
|完成通知|libuv 回调|CQE|
|上传 KV|TCP 发送数据|RDMA READ|
|下载 KV|TCP 接收数据|RDMA WRITE|
|存储管理|`kv_map` / LRU|`kv_map` / LRU|
|本次是否改造|没有|三 Poller、四队列|

最重要的三个结论：

1. TCP 和 RDMA 是两条独立的网络传输路径，共享 Service 的 KV 存储管理。
    
2. 原 RDMA 是单 CQ Poller 集中处理不同类型的完成事件，改造后拆成三个 Poller、四个任务队列。
    
3. TCP 使用 libuv 事件驱动，RDMA 使用 Verbs + CQ 完成事件驱动，两者的数据传输机制不同。
