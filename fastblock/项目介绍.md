
我研究的项目是 **FastBlock，一个基于 SPDK、RDMA 和 Multi-Raft 实现的高性能分布式块存储系统**。

这个项目主要针对传统分布式存储系统在 NVMe SSD 场景下存在的 CPU 开销较高、I/O 延迟较大，以及单卷性能难以充分发挥硬件能力等问题。

### 1. 整体架构

从整体上看，FastBlock 的架构和 Ceph 比较相似，主要分为三个部分：

**第一部分是 Monitor 集群。** 主要负责集群元数据管理，包括 OSDMap、PGMap、存储池以及存储卷等信息。

**第二部分是 OSD 存储集群。** 负责实际的数据存储。系统通过 PG 管理数据分布，并使用 Multi-Raft 实现多副本数据一致性。底层基于 SPDK Blobstore 实现数据和 Raft 日志的持久化。

**第三部分是客户端。** 负责将用户的块设备 I/O 请求转换成对象操作，再发送到对应 PG 的 Leader OSD 处理。

### 2. 核心技术设计

这个项目有三个比较重要的技术特点。

首先是 **SPDK 用户态存储框架**。通过用户态 NVMe 驱动、轮询和无锁消息传递等机制，减少传统内核 I/O 路径的开销。

其次是 **RDMA 网络通信**。FastBlock 的高频数据通信和 Raft RPC 使用 RDMA，目的是降低网络传输中的 CPU 消耗和延迟。

最后是 **Multi-Raft**。不同 PG 可以对应不同的 Raft Group，通过日志复制和状态机应用实现数据一致性。

### 3. RDMA RPC 框架设计

我目前重点研究的是 FastBlock 的 RDMA RPC 通信模块。

这个模块主要负责 Client 与 Server 之间的异步 RPC 通信，包括连接管理、请求序列化、数据传输、任务调度、方法分发和响应处理。

从架构上看，它有三个值得关注的设计。

**第一，基于 SPDK Thread 和 Poller 的事件驱动模型。**

RDMA Server 通过多个 Poller 分别处理连接事件、CQ 完成事件、RPC Task 和响应发送等工作。这些 Poller 可以运行在同一个 SPDK Thread 上，避免传统的一连接一线程模型带来的大量线程管理开销，同时使框架内部状态能够按线程归属集中管理。

**第二，RPC 任务采用异步流水线设计。**

框架将请求接收、数据准备、RPC 方法执行和响应发送划分为不同阶段。一个 RPC Task 在等待网络数据或者业务完成时，不会阻塞整个 SPDK Thread，Poller 可以继续处理其他任务。

**第三，根据请求大小选择不同的数据传输方式。**

小请求可以通过 SEND 直接携带请求数据，减少额外网络操作。

对于较大的普通 RPC 请求，客户端先通过 SEND 传递数据所在的远程内存地址、rkey 等元数据，服务端再主动发起 RDMA READ 获取请求内容。

这样可以兼顾小请求的低延迟和大数据传输的效率。

### 4. 我的研究重点

我主要围绕 RDMA RPC 框架的三个方面展开分析：

一是整个 RPC 从客户端发起到服务端执行，再到返回响应的生命周期。

二是 SPDK Thread、Poller 和跨线程消息传递组成的异步调度模型。

三是连接状态、RPC Task 状态，以及正常完成、超时和异常情况下的资源管理。

通过分析这些设计，我希望理解的是：如何在高性能存储系统中，把 RDMA 通信和异步 RPC 调度结合起来，在降低线程与锁开销的同时，保证请求的正确处理。
