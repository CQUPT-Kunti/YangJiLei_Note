# 什么是块存储

## 1. 什么是块存储

块存储（Block Storage）是一种以“块设备（Block Device）”形式提供存储资源的技术。

简单理解：

> 块存储给系统提供的是一块可以像本地硬盘一样使用的磁盘。

操作系统看到的通常类似：

```text
/dev/vdb
/dev/sdc
```

应用程序不会直接感知后面有多少台服务器，而是认为自己拥有一块普通硬盘。

例如：

```text
应用程序
    |
    ↓
文件系统（ext4/xfs）
    |
    ↓
块设备（/dev/vdb）
    |
    ↓
分布式块存储集群
    |
    ↓
多个存储节点 + 磁盘
```

---

# 2. 块存储解决什么问题

传统服务器：

```text
服务器
 |
本地硬盘
 |
数据库
```

问题：

- 容量有限
    
- 硬盘损坏可能导致数据不可用
    
- 服务器迁移困难
    
- 无法快速扩容
    

块存储：

```text
服务器
 |
虚拟磁盘
 |
分布式存储系统
 |
多个存储节点
```

提供：

- 高可靠
    
- 可扩展
    
- 快照
    
- 扩容
    
- 数据副本
    

---

# 3. 块存储和普通文件有什么区别

很多人看到：

```text
/data/user.txt
```

会认为这就是块存储。

实际上不是。

文件是建立在块存储之上的。

关系：

```text
块存储
    ↓
文件系统
    ↓
文件
```

例如：

```text
/dev/vdb

格式化

↓

ext4

↓

/data/user.txt
```

用户操作的是文件，但是底层可能使用块存储。

---

# 4. 块存储的数据组织方式

块存储本质上是一段连续的地址空间。

例如：

```text
磁盘空间

+------+------+------+------+------+
| Block|Block |Block |Block |Block |
|  1   |  2   |  3   |  4   |  5   |
+------+------+------+------+------+
```

每个块都有地址：

```text
Block 1
Block 2
Block 3
...
```

系统通过地址直接读取对应位置。

特点：

- 可以随机访问
    
- 延迟低
    
- 适合高频读写
    

---

# 5. 为什么数据库喜欢块存储

数据库不是简单存文件，而是管理自己的数据结构。

例如 MySQL InnoDB：

```text
数据库
 |
数据页(Page)
 |
文件系统
 |
块设备
```

InnoDB 默认一个 Page 大约：

```text
16KB
```

一个 Page 中可以存很多条记录：

```text
Page 1

+----------------+
| user 1         |
| user 2         |
| user 3         |
| ...            |
| user 128       |
+----------------+
```

数据库通过索引快速找到数据位置。

例如：

```sql
SELECT *
FROM user
WHERE id=100;
```

流程：

```text
B+树索引
    ↓
找到数据所在Page
    ↓
读取Page
    ↓
修改或返回数据
```

---

# 6. 为什么数据库需要随机访问

假设用户查询：

```sql
SELECT *
FROM user
WHERE id=888;
```

数据库通过索引知道：

```text
id=888
在某个Page
```

然后直接读取：

```text
Page 50000
```

而不是：

```text
Page 1
Page 2
Page 3
...
```

这种直接定位就是随机访问。

数据库大量依赖：

- 随机读取
    
- 随机写入
    
- 高 IOPS
    

因此块存储非常适合数据库。

---

# 7. 数据库中的索引和块存储关系

数据库通常不会给每个字段自动建立索引。

例如：

用户表：

```text
id
username
age
address
```

可能：

```text
id
 ↓
B+树索引
```

如果经常：

```sql
WHERE username='tom'
```

才建立：

```text
username
 ↓
B+树索引
```

没有索引：

```text
扫描所有数据Page
```

有索引：

```text
B+树
 ↓
定位Page
 ↓
读取数据
```

# 8. 块存储的典型应用场景

## 8.1 云服务器磁盘

例如云服务器：

```text
虚拟机
 |
系统盘
数据盘
 |
云块存储
```

用于：

- Linux系统盘
    
- 应用数据
    
- 日志
    

---

## 8.2 数据库

常见：

- MySQL
    
- PostgreSQL
    
- Oracle
    
- SQL Server
    

原因：

- 大量随机IO
    
- 数据持续修改
    
- 需要低延迟
    

---

## 8.3 Kubernetes 持久化存储

容器删除后数据不能丢：

```text
Pod
 |
PVC
 |
块存储
```

用于：

- MySQL容器
    
- Redis持久化
    
- Elasticsearch
    

---

## 8.4 虚拟化平台

例如：

```text
物理服务器
 |
虚拟机
 |
虚拟磁盘
 |
块存储
```

用于：

- VMware
    
- OpenStack
    
- KVM
    

---

# 9. 块存储、文件存储、对象存储区别

|类型|提供什么|适合场景|
|---|---|---|
|块存储|一块硬盘|数据库、虚拟机、云服务器|
|文件存储|文件目录|共享文件、NAS|
|对象存储|对象+Key|图片、视频、备份|

例如：

电商系统：

```text
订单数据库
    ↓
块存储

商品图片
    ↓
对象存储

共享文件
    ↓
文件存储
```

---

# 10. 分布式块存储

传统块存储：

```text
一台存储服务器
 |
硬盘
```

分布式块存储：

```text
存储集群

节点1
节点2
节点3

共同提供一个虚拟磁盘
```

例如：

- Ceph RBD
    
- 云厂商云硬盘
    
- OpenStack Cinder
    

特点：

- 数据副本
    
- 故障恢复
    
- 在线扩容
    
- 横向扩展
    

---

# 总结

块存储可以理解为：

> 给服务器或应用提供一块可靠、高性能、可随机读写的虚拟硬盘。

它主要解决：

- 数据库需要高速随机IO
    
- 虚拟机需要稳定磁盘
    
- 容器需要持久化数据
    
- 企业需要高可靠存储
    

数据库、云服务器、虚拟化平台是块存储最典型的应用场景。
